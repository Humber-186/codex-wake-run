# Wake Run Economic Monitor

## 预期目标

为 wake-run 增加可选的经济看护模式：使用明确指定的低成本 Codex 模型对长任务完成事件进行结构化分诊，在主 agent 预先授权的范围内执行原命令重试，并把成功、复杂异常或监护失败可靠地升级回主线程。监护能力不得削弱现有直接唤醒模式的可靠性，也不得允许监护 agent 递归创建新的 wake-run 任务。

## 行进状态

- 状态：已完成
- 当前阶段：交付验证完成

## 验收标准

- 经济看护为显式可选模式，未启用时保持当前行为。
- 主 agent 必须通过持久化计划明确模型、监护说明、日志证据范围和允许的自动处置。
- 监护会话在目标进程启动前创建并确认；创建失败不得返回 `armed`。
- 监护模型仅返回结构化决策，确定性执行器只接受经过计划授权的原命令重试。
- 成功、复杂异常、无效决策及监护调用失败均形成可审计 completion 并唤醒主线程。
- 监护上下文具有角色、根 run、深度和计划摘要，监护角色无法再次启动 wake-run。
- 重试、分诊与投递使用稳定标识和持久状态，重复投递不重复执行处置。
- 自动化测试覆盖计划校验、会话创建、成功分诊、授权重试、越权决策、递归拒绝和直接模式回归。
- Skill 指令及中英文 README 与实际行为一致。

## 最终已交付成果

- 新增严格的用户监护计划与带哈希的运行时计划，固定模型、说明、日志证据和处置授权。
- 新增独立只读 Codex 监护会话的同步创建、结构化 readiness 和事件时 `exec resume` 分诊。
- 新增 `report_success`、`retry_exact`、`escalate` 决策协议及确定性校验；只有正常结束的非零退出可在授权内原命令重试。
- worker 支持同一 run 内的精确重试，并在 completion 中持久化全部执行尝试、监护决策、模型、会话、计划哈希和错误。
- 监护调用失败、协议越权、复杂异常和正常终态均可靠投递回主线程；直接模式行为保持兼容。
- 新增基于角色、根 run 和深度的递归拒绝，监护环境无法启动或补发 wake-run。
- 新增经济看护参考文档，并同步 Skill 与中英文 README。
- 52 项测试通过、2 项 Windows 专属测试在 Linux 跳过；Python 编译、warnings-as-errors、diff 检查与 Skill 校验通过。
- 使用真实 Codex CLI 0.154.0 和 `gpt-5.6-luna` 验证会话创建、`thread.started` 解析、持久会话恢复及结构化成功分诊；临时验证会话已归档。
