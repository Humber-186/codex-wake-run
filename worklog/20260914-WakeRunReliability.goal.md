# Wake Run Reliability

## 预期目标

将 wake-run 从“通常能够完成后台执行并唤醒”提升为具有明确启动确认、持久化投递状态和可恢复补发能力的可靠 Codex Skill；所有失败均可观察，不以静默降级伪装成功。

## 行进状态

- 状态：已完成
- 当前阶段：交付验证完成

## 验收标准

- launcher 仅在 worker 完成必要初始化且目标进程成功启动后返回 `armed`。
- 启动失败、握手超时和 worker 提前退出均返回明确错误。
- 完成事件具有持久化状态、投递尝试信息及可执行的补发入口。
- 重复唤醒具有明确的投递语义和稳定事件标识。
- queue 与预检超时严格受配置的总时限约束。
- 状态写入、启动握手写入等关键错误不被静默吞掉。
- 日志及状态文件采用受限权限；成功启动后清理临时握手文件，失败状态保留用于诊断。
- 关键异常路径均有有效自动化测试，Linux 测试与 Skill 校验通过。
- README、SKILL 使用约定与实际行为一致。

## 最终已交付成果

- 严格的 worker/目标进程启动握手，以及同步启动错误与超时处理。
- 具有原子落盘、投递状态、累计尝试次数、稳定事件标识和进程锁的 completion outbox。
- 未送达事件的显式补发入口及 at-least-once 重复事件约定。
- queue/preflight 有界超时、POSIX 私有权限与状态完整性校验。
- completion 持久化失败的显式失败唤醒路径。
- 按职责拆分且符合代码指标的 CLI、平台、状态、worker 与核心模块。
- 覆盖正常运行、失败、恢复、并发锁、损坏状态、CLI 补发、Linux 集成和 Windows 专属路径的自动化测试。
- 与实际行为一致的 Skill 指令和中英文 README。
